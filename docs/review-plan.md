# План проверки кода (Code Review Plan)

## 1. Цель проверки

Обеспечить качество, надёжность и безопасность микросервиса расчёта скидок интернет-магазина.

## 2. Объекты проверки

- Корректность расчёта скидок.
- Обработка промокодов.
- Учёт уровня клиента.
- Ограничение максимальной скидки.
- Качество и читаемость Python-кода.
- Соблюдение стандартов Flake8.

## 3. Критерии качества

- Все проверки GitHub Actions должны проходить успешно.
- Код должен соответствовать PEP 8.
- Не должно быть критических ошибок.
- Расчёт скидок должен соответствовать бизнес-правилам.
- Изменения должны проходить Code Review.

## 4. Роли участников

- Разработчик: пишет и исправляет код.
- Ревьюер: проверяет изменения.
- Ответственный за проект: принимает решение об объединении изменений.

## 5. Метрики качества

- 100% успешных проверок Flake8.
- 0 критических замечаний перед объединением.
- Не менее одного одобрения Pull Request.
- Все найденные ошибки должны быть исправлены.

## 6. Порядок проверки

1. Разработчик создаёт Pull Request.
2. GitHub Actions запускает Flake8.
3. Ревьюер проверяет изменения.
4. Разработчик исправляет замечания.
5. Проверки запускаются повторно.
6. После успешной проверки изменения объединяются.

## 7. Эскалация проблем

Если обнаружена критическая ошибка, объединение блокируется.

Если участники не могут согласовать решение, вопрос передаётся ответственному за проект.

## 8. Итог

План обеспечивает контроль качества кода и снижение риска ошибок в работе микросервиса.
